```text Base URL
https://api-bc.userecord.io/api/v1/partner/white-collar
```

You need two things: your **key id** and your **secret**. The signature, timestamp and `Idempotency-Key` are generated for you. Copy the `call()` helper from [Authentication](/white-collar-api/authentication#signing-helper) first: the code samples on each endpoint page use it.

## Try it

Every endpoint page has a **Try it** button. Enter your key id in `x-api-key` and your secret in `x-secret-key`, fill the request and press **Send**. `x-secret-key` is only a form field: the page signs the request in your browser and removes the secret before sending. See [Why does Try it say `x-secret-key`?](/white-collar-api/authentication#why-does-try-it-say-x-secret-key).

<Warning>
  Campaign calls email real candidates and spend credits, even with a TEST key.
</Warning>

## On each endpoint page

- **Scope**: the scope the key needs. Any one listed is enough.
- **Idempotency-Key**: whether the endpoint needs one, accepts one, or ignores it. Try it makes one for you.
- **Responses**: the success answer and the errors specific to that endpoint. Errors any endpoint can return, such as `401`, `429` and `500`, are listed in [Errors](/white-collar-api/reference/errors).

## Endpoints

| Group | What it covers |
|---|---|
| Workflows | The container your job mandates run under. |
| Job mandates | The role and its assessment settings; close and reopen. |
| Questions | Have Record write the assessment, or supply your own. |
| Campaigns | Invite candidates and manage the batch. |
| Results | Candidate rows, results and verdicts. |
| Analytics | Invited, completed, hired, rejected and average score. |
| Lookups | The question types and difficulties. |
| Events | Pull result events and confirm them in the same call. |
| Webhooks | Endpoints that receive result events, and their delivery logs. |
