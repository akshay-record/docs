Record emails each candidate a link to a timed assessment, grades it, and gives you a score and a hire / reject verdict. The White Collar API lets your ATS or backend run that whole flow and receive every result.

## Assess candidates from your own system, in 4 steps

Do the steps in this order. Each one returns an id that the next one needs.

<Steps>
  <Step title="Workflow">
    The container your roles run under, and whether Record emails the candidates. Create it once and reuse it. You get `workflow_id`.
  </Step>
  <Step title="Job mandate and questions">
    The role and its assessment: difficulty, which question types, how many, marks, pass mark and duration. Then have Record write the questions, or supply your own. Needs `workflow_id`, you get `mandate_id`.
  </Step>
  <Step title="Campaign">
    The people: name and email of each candidate. Record emails them. Needs `mandate_id` with `ready` questions, you get `campaign_id`.
  </Step>
  <Step title="Results">
    Score and verdict for each candidate, sent to your webhook as soon as they finish. You get `candidate_id`.
  </Step>
</Steps>

## The 8 calls you need

1. [`POST /workflows`](/white-collar-api/guides/workflows#create-a-workflow) → save `workflow_id`
2. [`POST /mandates`](/white-collar-api/guides/job-mandates#create-a-job-mandate) → save `mandate_id`
3. [`POST /mandates/{mandate_id}/questions/generate`](/white-collar-api/guides/job-mandates#have-record-write-the-questions) → `questions.status` becomes `ready`
4. [`POST /campaigns`](/white-collar-api/guides/campaigns#create-a-campaign) → save `campaign_id`; invitations go out in the background
5. [`GET /campaigns/{campaign_id}`](/white-collar-api/guides/campaigns#list-and-get-campaigns) → watch it go from `sending` to `sent`
6. [`POST /webhooks/endpoints`](/white-collar-api/guides/webhooks#create-an-endpoint) → results are sent to you, signed; answer 2xx to confirm. No public URL? Pull them with [`POST /events/pull`](/white-collar-api/guides/webhooks#pull-and-confirm-events)
7. [`GET /campaigns/{campaign_id}/candidates`](/white-collar-api/guides/results#list-the-candidates-of-a-campaign) → catch up or check: status, score and verdict
8. [`GET /analytics/mandates/{mandate_id}`](/white-collar-api/guides/results#analytics) → invited, completed, hired, rejected, average score

## 4 rules to remember

- You only need your **key id and secret**. Timestamp, signature and `Idempotency-Key` are made by the [helper](/white-collar-api/authentication#signing-helper) (or by **Try it**).
- Creating calls carry an `Idempotency-Key`, so a retry never creates twice. The helper adds it.
- Use a **TEST key** first. A campaign emails real people and spends credits.
- Every error is `{ "success": false, "error": { "code", … } }`; all codes are explained in [Errors](/white-collar-api/reference/errors).

## What a candidate goes through

A candidate gets an email with a link, takes the assessment in the time you set, and submits. Record grades it and writes feedback. The attempt ends when it is submitted (or timed out or disqualified, and then submitted), and that is when you get its result.

| You set | On the job mandate |
|---|---|
| Difficulty | `easy`, `medium` or `hard`. |
| Question types | `mcq`, `true-false`, `short-answer`, `long-answer`, `coding`: how many of each, and the marks for each. |
| Pass mark | The score that counts as a pass (verdict `hire`). Below it is `reject`. |
| Duration | Minutes the candidate has. |

## Before you start

- An API key pair from the Record playground, under **Settings → API keys**.
- The White Collar API switched on for that key. Record does this by granting [scopes](/white-collar-api/authentication#scopes).
- A **TEST** key for development. It sees only test data, and its emails are still real.
