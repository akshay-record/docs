Do not poll for results. Give Record an HTTPS URL; when a candidate finishes, Record POSTs the result record to it, **signed with your API secret key**, and keeps retrying until you answer with a **2xx**. Nothing is dropped: anything you do not acknowledge comes again, can be pulled from the event feed, and can be replayed.

| You send | You get | Scopes |
|---|---|---|
| an HTTPS URL (`POST /webhooks/endpoints`) | one `candidate.result` event per finished candidate | `webhooks:manage` (endpoints), `events:read` (feed) |

## When an event is sent

Once, when a candidate reaches `completed`, `declined` or `failed` and their result has stayed the same for about 45 seconds (the last questions are answered after the skill result exists, so Record waits instead of sending one event per answer). If a finished result later changes (a re-grade), you get a new event with a higher `version` for the same candidate.

```http
POST /hooks/record HTTP/1.1
Content-Type: application/json
User-Agent: Record-Webhooks/1.0
Record-Event-Id: evt_9c2e4a6b8d0f1234567890abcdef1234
Record-Delivery-Id: dlv_7a1b3c5d7e9f0123456789abcdef0123
Record-Attempt: 1
Record-Signature: t=1791204071,v1=5f2b…

{
  "event_id": "evt_9c2e4a6b8d0f1234567890abcdef1234",
  "type": "candidate.result",
  "api_version": "2026-10-01",
  "created_at": "2026-10-05T12:41:11Z",
  "mode": "live",
  "version": 1,
  "sequence": 482913,
  "data": { "...": "the record shown in Results" }
}
```

| Field | Description |
|---|---|
| `event_id` | Stable forever. Use it to skip repeats. |
| `type` | `candidate.result` (or `webhook.test` from the test endpoint). |
| `version` | Rises each time the same candidate's result changes. Keep the highest. |
| `sequence` | Order of events in your stream. |
| `mode` | `live` or `test`. |
| `data` | The [result record](/blue-collar-api/guides/results#the-record). |

## What your server must do

1. **Verify the signature** (below), then **answer 2xx within 10 seconds**. That is the acknowledgement. Process the event after answering.
2. **Keep the `event_id`** of what you processed and skip repeats: delivery is at-least-once, so the same event can arrive twice.
3. **Keep the highest `version`** per candidate; ignore an older one that arrives late.
4. Any other answer, a timeout or a connection error means "not received": Record retries.

## Retries and nothing lost

| | |
|---|---|
| Retry waits | 30 s, 2 min, 10 min, 30 min, 1 h, 2 h, 4 h, 8 h, 12 h, 24 h (about 52 hours), then the delivery is kept as `dead`: visible in the delivery log and replayable with `POST /webhooks/deliveries/{delivery_id}/retry`. A `Retry-After` header in your answer is respected. |
| Endpoint down for long | After 20 failures in a row the endpoint is `auto_paused`. Events keep being recorded and wait. Fix it, then `PATCH` its status to `active`: they are sent, oldest first. |
| Event feed | `GET /events` returns every event you have not acknowledged, oldest first; confirm with `POST /events/ack`. Use it as a safety net next to the webhook, or instead of it if you cannot expose a URL. Events are kept 30 days. |
| Past results | Create the endpoint with `backfill_from`, or call `POST /webhooks/endpoints/{endpoint_id}/backfill`, to receive results from the last 30 days at most. |
| Test | `POST /webhooks/endpoints/{endpoint_id}/test` sends a signed `webhook.test` now and shows what your server answered. |

## Verify the signature

Each delivery has `Record-Signature: t=<seconds>,v1=<hex>`. Compute HMAC-SHA256 of `<t>.<raw request body>` with your **API secret key** (`VFN_SK_…`, the same one you sign your own calls with) and compare to `v1`. Reject if `t` is more than 5 minutes old. Nothing else to configure.

<CodeGroup>

```javascript Node
// Express: use the RAW body, not a parsed one.
const crypto = require("crypto");

app.post("/hooks/record", express.raw({ type: "application/json" }), (req, res) => {
  const header = req.get("Record-Signature") || "";
  const t = (header.match(/t=(\d+)/) || [])[1];
  const sigs = [...header.matchAll(/v1=([a-f0-9]{64})/g)].map((m) => m[1]);
  const expected = crypto
    .createHmac("sha256", process.env.RECORD_API_SECRET)
    .update(`${t}.${req.body.toString("utf8")}`)
    .digest("hex");

  const fresh = Math.abs(Date.now() / 1000 - Number(t)) < 300;
  const valid = sigs.some((s) => crypto.timingSafeEqual(Buffer.from(s), Buffer.from(expected)));
  if (!t || !fresh || !valid) return res.status(400).end();

  res.status(200).end(); // acknowledge first
  const event = JSON.parse(req.body.toString("utf8"));
  // then: skip if event.event_id was already processed; ignore an older version; store event.data
});
```

```python Python
import hashlib, hmac, os, re, time
from flask import Flask, request

app = Flask(__name__)

@app.post("/hooks/record")
def record_hook():
    raw = request.get_data()  # the raw body
    header = request.headers.get("Record-Signature", "")
    m = re.search(r"t=(\d+)", header)
    sigs = re.findall(r"v1=([a-f0-9]{64})", header)
    if not m or abs(time.time() - int(m.group(1))) > 300:
        return "", 400
    expected = hmac.new(os.environ["RECORD_API_SECRET"].encode(),
                        f"{m.group(1)}.".encode() + raw, hashlib.sha256).hexdigest()
    if not any(hmac.compare_digest(s, expected) for s in sigs):
        return "", 400
    # acknowledge now; hand the event to a queue and process it there
    return "", 200
```

</CodeGroup>

Your URL must be HTTPS on port 443 and reachable from the internet. Redirects are not followed. You can have up to 5 endpoints.

## Webhook endpoints

### Create an endpoint

`POST /webhooks/endpoints`

Register the HTTPS URL that receives result events. Deliveries are signed with your API secret key.

**Scope:** `webhooks:manage` · **Idempotency-Key:** optional

| Field | Type | Description |
|---|---|---|
| `url` | `string` | **Required.** HTTPS, port 443, a public host. Any 2xx answer counts as the acknowledgement. |
| `description` | `string` | Up to 200 characters. |
| `event_types` | `array<string>` | Default `candidate.result`. |
| `backfill_from` | `string` | ISO date-time: also send results from then on (at most 30 days back). |

<CodeGroup>

```javascript JavaScript
const res = await call("POST", "/api/v1/partner/webhooks/endpoints", {
  "url": "https://ats.example.com/hooks/record",
  "description": "Production ATS",
  "event_types": ["candidate.result"]
});
const { data } = await res.json();
```

```python Python
res = call("POST", "/api/v1/partner/webhooks/endpoints", {
```

### Update an endpoint

`PATCH /webhooks/endpoints/{endpoint_id}`

Send only what changes. `status: paused` holds deliveries (nothing is lost); `status: active` resumes them, oldest first. Use it to bring back an `auto_paused` endpoint.

**Scope:** `webhooks:manage` · **Idempotency-Key:** optional

| Field | Type | Description |
|---|---|---|
| `url` | `string` | Your HTTPS endpoint (port 443, public host). Record POSTs each event here and counts any 2xx as the acknowledgement. |
| `description` | `string` | At most 200 characters. |
| `event_types` | `array<string>` | Each one of `candidate.result`. 1 to 1 items. |
| `status` | `string` | One of `active`, `paused`. |

```javascript JavaScript
const res = await call("PATCH", "/api/v1/partner/webhooks/endpoints/we_3f9a1c7e5b2d4086a1b3c5d7e9f01234", { "status": "paused" });
```

### Acknowledge events

`POST /events/ack`

Up to 100 ids. They stop coming back and no webhook retry is sent for them. Safe to repeat.

**Scope:** `events:read`

| Field | Type | Description |
|---|---|---|
| `event_ids` | `array<string>` | **Required.** 1 to 100 items. |

<CodeGroup>

```javascript JavaScript
const res = await call("POST", "/api/v1/partner/events/ack", {
  "event_ids": ["evt_9c2e4a6b8d0f1234567890abcdef1234"]
});
const { data } = await res.json();
```

```python Python
res = call("POST", "/api/v1/partner/events/ack", {
    "event_ids": ["evt_9c2e4a6b8d0f1234567890abcdef1234"]
})
data = res.json()["data"]
```

```bash cURL
pcall POST "/api/v1/partner/events/ack" '{
  "event_ids": ["evt_9c2e4a6b8d0f1234567890abcdef1234"]
}'
```

```json 200 Response
{
  "success": true,
  "data": { "acknowledged": 1 }
}
```

</CodeGroup>

| Error | When |
|---|---|
| 400 `VALIDATION_FAILED` | More than 100 ids, or an id that is not an event id. |

Can also return the [common errors](/blue-collar-api/reference/errors). [Full schema](/api-reference/events/acknowledge-events)
