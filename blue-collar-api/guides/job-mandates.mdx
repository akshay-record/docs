A mandate is the job Record checks candidates against: its skills, screening questions and checks. Record writes the questions in the background.

| Needs | You get | Scope |
|---|---|---|
| `workflow_id` from [step 1](/blue-collar-api/guides/workflows) | `mandate_id`, then wait for `status: ready` | `mandates:write` to change, `mandates:read` to read |

Before you create one, pick its [skills](/blue-collar-api/guides/skills) and, if you want, its [place, employment type and shift](/blue-collar-api/guides/lookups).

## Rules the server checks

- 5–10 skills (max 10). Fewer than 5 is accepted with a warning.
- At most 3 skills with `verify: true`, and only skills that are `verifiable`.
- At most 5 screening questions, of type `yes_no` or `voice`. The schema also lists `single_choice`, `number`, `short_text` and `options`; they are not supported yet and answer `400 VALIDATION_FAILED`.
- If `skill_verification` is on, you need at least 1 verified skill.
- If `data_enrichment` is on, you need at least 1 question.
- The job is in India (`location`) **or** abroad (`location_type: "abroad"` + 1–10 `countries`), never both.
- Experience is whole years, 0–50.

## Preparing and ready

A new mandate answers `202 Accepted` with `status: "preparing"` while Record writes the skill questions:

```text
preparing  →  ready      (or failed)
```

Repeat `GET /mandates/{mandate_id}` until `status` is `ready`. A campaign created while the mandate is still preparing waits and goes out by itself once it is ready. Each change makes a new `flow_version`.

## After it is created: what can you change?

| Part of the mandate | Replace it? | How |
|---|---|---|
| Whole mandate | Yes | `PUT /mandates/{mandate_id}` with the full body. |
| Skills | Yes | `PUT …/skills` |
| Screening questions | Yes | `PUT …/questions` or `PUT …/enrichment-questions` (1–5, your own text) |
| Which checks run | Yes | `PUT …/methods` |
| Skill questions (the 3 Record writes) | Regenerate only | `PUT …/questions` with `skill_questions.regenerate`: all 3 or chosen slots. Record writes the new text; you cannot supply or edit it. Changing which skills have `verify: true` also regenerates them. Read them with `GET …/questions`. |
| Interest questions | No | A fixed prompt per language ("Apart from the job, what other work have you done?"). You can only switch it on or off by adding or removing `interest_collection` in `methods`. |

Any change is refused with `409 CONFLICT` while the mandate is `preparing` (wait for `Retry-After`), and a mandate takes at most 10 changes an hour. Only mandates created through the API can be changed; playground mandates answer `403 FORBIDDEN`.

## Close the job

Archive the mandate when the job is filled: no new campaigns start, running ones finish, and results stay readable. `DELETE` does the same. Nothing is erased.

## Endpoints

### Create a job mandate

`POST /mandates`

Create the job Record verifies candidates against. Returns `mandate_id`; questions are prepared in the background.

**Scope:** `mandates:write` · **Idempotency-Key:** required

| Field | Type | Description |
|---|---|---|
| `workflow_id` | `string` | **Required.** From step 1. |
| `title`, `company_name` | `string` | **Required.** Plain text, up to 200 characters. |
| `skills` | `array<object>` | **Required.** `{ skill_id, verify }` or `{ name, pending: true }` (a skill you requested). 5–10 recommended, max 10; max 3 with `verify: true`. |
| `methods` | `array<string>` | Which checks run. Leave out to use the workflow’s `default_methods`. |
| `enrichment_questions` | `array<object>` | 1–5 items `{ key, type: yes_no \| voice, text, knockout: yes \| no, required }`. Needed when `data_enrichment` is on. |
| `job_id` | `string` | Your own job id. If you send it, it must not be in use. |
| `location_type` | `string` | `india` (default) or `abroad`. Same as the playground’s Abroad option. |
| `location` | `object` | A place in India: `{ city, state?, pincode? }` (find it with `GET /locations`). Not allowed when `location_type` is `abroad`. |
| `countries` | `array<string>` | **With `abroad`.** Needed when `location_type` is `abroad`: 1–10 different ISO 3166-1 alpha-2 codes such as `SG` (list them with `GET /countries`; lower case is accepted and stored upper case). India (`IN`) cannot be picked. Not allowed for an India job. |
| `experience` | `object` | `{ min_years, max_years }`, whole years 0–50, `max_years` at least `min_years`. Send both. Leave it out to clear it on a replace. |
| `employment_type`, `shift` | `string` | Pick from `GET /employment-types` (Full-time, Part-time, Contract, …) and `GET /shifts` (Day shift, Night shift, Rotational, General). Other text up to 100 characters is kept as sent. |
| `openings`, `salary`, `description`, `owner` | `integer`, `object`, `string` | Job details. `description` up to 1,500 characters. |
| `interest_collection` | `object` | `other_roles` is only saved and returned. It does not change what candidates are asked: the interest prompt is fixed, and `methods` switches it on or off. |

| Error | When |
|---|---|

### Update mandate questions

`PUT /mandates/{mandate_id}/questions`

The write side of `GET …/questions`: replace the screening questions, or ask Record to write new skill questions. One part per call.

**Scope:** `mandates:write` · **Idempotency-Key:** required

| Field | Type | Description |
|---|---|---|
| `enrichment_questions` | `array<object>` | **One of the two.** Replaces the screening questions (1–5), exactly like `PUT …/enrichment-questions`. Send this part alone. Each item is `{ key, type, text, knockout, required }`, as in Create a job mandate. |
| `skill_questions.regenerate` | `object` | **One of the two.** `"all"` or the slots to write again, e.g. `[0, 2]` (the `index` in `GET …/questions`). Record writes the new text; you cannot supply or edit it. Send this part alone. |
| `interest questions` | — | **Not editable.** A fixed prompt per language. Switch it on or off with `methods`. |

<CodeGroup>

```javascript JavaScript
const res = await call("PUT", "/api/v1/partner/mandates/JM_261009101612456H3N8W2L5C9V1Z4/questions", {
  "skill_questions": { "regenerate": "all" }
});
const { data } = await res.json();
```

```python Python
res = call("PUT", "/api/v1/partner/mandates/JM_261009101612456H3N8W2L5C9V1Z4/questions", {
    "skill_questions": {"regenerate": "all"}
})
data = res.json()["data"]
```

pcall PUT "/api/v1/partner/mandates/JM_261009101612456H3N8W2L5C9V1Z4/questions" '{
  "skill_questions": { "regenerate": "all" }

### Replace a job mandate

`PUT /mandates/{mandate_id}`

Replace the whole mandate (send the full body again). An identical resend changes nothing.

**Scope:** `mandates:write` · **Idempotency-Key:** optional

| Field | Type | Description |
|---|---|---|
| `workflow_id` | `string` | **Required.** One of your workflows. |
| `title` | `string` | **Required.** 1 to 200 characters. |
| `company_name` | `string` | **Required.** 1 to 200 characters. |
| `location_type` | `string` | Where the job is: "india" (default; give `location`) or "abroad" (give `countries`). Same as the playground's Abroad option. |
| `location` | `object` | A place in India (find it with GET /locations). Leave it out for an abroad job. Fields: `city`, `state`, `pincode`. |
| `countries` | `array<string>` | Only with location_type "abroad": 1 to 10 ISO 3166-1 alpha-2 codes such as SG (list them with GET /countries). India is not selectable. |
| `experience` | `object` | Whole years, 0 to 50. Fields: `min_years`, `max_years`. |
| `openings` | `integer` | 1 to 100000. |
| `salary` | `object` | Fields: `min`, `max`, `currency`, `period`. |
| `description` | `string` | Up to 1,500 characters (the question generator's limit). |
| `shift` | `string` | Use a value from GET /shifts so the playground shows it as a choice; any other text is kept as sent. |
| `employment_type` | `string` | Use a value from GET /employment-types so the playground shows it as a choice; any other text is kept as sent. |
| `owner` | `object` | The recruiter in your ATS; defaults to x-on-behalf-of. Fields: `external_user_id`, `name`. |
| `methods` | `array<string>` | Any non-empty mix; candidates always go enrichment → skills → interest. Omit to use the workflow's default. Each one of `data_enrichment`, `skill_verification`, `interest_collection`. |
| `skills` | `array<object>` | **Required.** 5 to 10 recommended; fewer than 5 is a warning. Fields: `skill_id`, `verify`, `name`, `pending`. |
| `enrichment_questions` | `array<object>` | 0 to 5 enrichment questions. Fields: `key`, `type`, `text`, `options`, `knockout`, `required`. |
| `interest_collection` | `object` | Fields: `other_roles`. |
