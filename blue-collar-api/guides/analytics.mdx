---
title: "Analytics"
description: "Funnel, channel and drop-off numbers for a workflow, job mandate or campaign."
---

The same numbers the Record playground shows on a workflow's Overview: how many invites went out, how many candidates started and finished, which channel they finished on, follow-ups, calls, where people drop off, completion by language and what other work candidates would take. Counts only: no names or phone numbers.

| Needs | You get | Scope |
|---|---|---|
| `workflow_id`, `mandate_id` or `campaign_id` from the steps above | funnel, channels, follow-ups, calls, drop-offs, languages | `analytics:read` |

## What you get

| Section | Contents |
|---|---|
| `assigned_candidates` | Candidates added to the campaigns in scope. |
| `tracked_candidates` | Candidates with a status row in the logs. |
| `funnel` | `sent` (invites sent), `started` (replied interested or started the verification), `not_started` and `completed` (finished with a verdict). |
| `verification_methods` | Completions by `video` (verification link) and `audio` (phone call). |
| `whatsapp` | Messages `sent`, `delivered`, `replied`, `failed`, and completions through WhatsApp. |
| `follow_ups` | Candidates reached by the first message and each follow-up, and `completed_after_follow_up` (completed after at least one nudge). |
| `calls` | Calls `initiated`, `completed`, `not_answered` and `not_interested`. |
| `channel_conversions` | Completions by `whatsapp`, `sms` and `phone_call`. |
| `drop_offs` | Count and percentage for `sent_not_started`, `started_no_verification` and `completed_no_verdict`. |
| `completion_by_language` | `reached`, `completed` and `completion_rate` per language. |
| `other_interests` | How many completed candidates are `open_to_other` roles, the roles they named, and their experience. |

## Endpoints

### Get workflow analytics

`GET /analytics/workflows/{workflow_id}`

The workflow Overview numbers from the Record playground. Add `mandate_id` and/or `campaign_id` to narrow it to one job or campaign; each must belong to this workflow.

**Scope:** `analytics:read`

| Query | Type | Description |
|---|---|---|
| `mandate_id` | `string` | Only this job mandate. |
| `campaign_id` | `string` | Only this campaign. |

<CodeGroup>

```javascript JavaScript
const res = await call("GET", "/api/v1/partner/analytics/workflows/WF_BG_261009101530123K7M2P9Q4X7R5T8");
const { data } = await res.json();
```

```python Python
res = call("GET", "/api/v1/partner/analytics/workflows/WF_BG_261009101530123K7M2P9Q4X7R5T8")
data = res.json()["data"]
```

### Get mandate analytics

`GET /analytics/mandates/{mandate_id}`

The numbers shown on the job mandate Overview in the Record playground, adding up all campaigns sent on the mandate. Add `campaign_id` to look at one campaign; it must belong to this mandate. The `analytics` object has its own shape, described below, not the workflow one above.

**Scope:** `analytics:read`

| Query | Type | Description |
|---|---|---|
| `campaign_id` | `string` | Only this campaign of the mandate. |

#### What you get

Each person counts once, by their latest invite, even if they were invited in several campaigns.

| Section | Contents |
|---|---|
| `campaigns`, `campaign_count` | The campaigns sent on the mandate (`campaign_id`, `name`), newest first, and how many are in scope: all of them, or 1 when you narrow to a `campaign_id`. |
| `reached` | People whose invite was sent. |
| `interested`, `not_interested`, `no_response`, `in_progress`, `completed` | Where those people stand. `not_interested` counts anyone who said no, even if they then finished, so such a person is in both `not_interested` and `completed`. |
| `avg_time_to_complete_ms` | Average time from first answer to completion, in milliseconds. `null` when there is no data yet. |
| `verdicts` | Completed skill assessments by verdict: `good_fit`, `maybe`, `not_fit` and `pending` (completed, verdict not ready), with their `total`. People who said no are left out. |
| `reach` | `whatsapp` (reached on WhatsApp), `no_whatsapp` (phone call only), `called` and `calls_answered`. |
| `interest_source` | Where interested people said yes: `whatsapp_button`, `job_page` and `phone_call`. One person can count in several, so these need not add up to `interested`. |
| `languages` | Completed people by the language they spoke, most first, `not detected` last. Adds up to `completed`. |
| `channels` | For `whatsapp`, `sms` and `phone`: `reached`, `responded`, `interested`, `not_interested` and `completed`. |
| `other_interests` | Whether it is `enabled`, how many `answered` (split into `answered_completed` and `answered_declined`), how many are `open` to another role, the top `roles` and `other_roles` (people who named a role outside them), `current_role` and `experience` buckets. |
| `follow_ups` | `after_follow_up` (completed after at least one nudge), the channel they came back on (`by_channel`) and the last message stage before they responded (`by_stage`: `initial`, `follow_up_1`, `follow_up_2`, `calls`). |
