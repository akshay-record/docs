A result is what Record **collected** from the candidate: the answers to your screening questions, the skill-verification verdict and score, and other roles they are open to. It comes as one record per candidate. The best way to get it is the [webhook](/blue-collar-api/guides/webhooks); these endpoints are for catching up and checking.

| Needs | You get | Scope |
|---|---|---|
| `campaign_id` from [step 3](/blue-collar-api/guides/campaigns) | a record with `status` and `output` | `results:read` |

## Status

| Status | Meaning |
|---|---|
| `pending` | Invited or answering; not finished. Read endpoints only, never sent by webhook. |
| `completed` | Finished. `output` holds what Record collected. |
| `declined` | The candidate said they are not interested. |
| `failed` | No result could be got. `reason` is `undeliverable` (the invite could not be delivered) or `no_response` (every attempt went unanswered). |

- **Your own fields.** Send up to 10 fields of your own as `metadata` (with `external_id`) when you add a candidate: they come back unchanged on every result.
- **Sections.** A section of `output` appears only once its data exists and only if that check ran for the job.
- **Screening answers** are keyed by the question text. `qualified` is `true` when every yes/no answer is the wanted one (the opposite of its `knockout`, or `yes` when no knockout is set), and `null` when there is no yes/no answer to judge. `answers_native` holds the original-language text of voice answers.
- **Skill verification** gives the `verdict`, `total_score`, an `evidenceClass` per skill (`Sufficient`, `Partial`, `Minimal`, `Incorrect` or `No Response`), and how many questions were `answered` of `total`. `answers` holds what the candidate said to each question, with its `evidenceClass`, its `score` as score and maximum in one value (like `7.5/10`) and a `summary`.
- **Video or phone call.** The recording depends on how the candidate verified. On the video link, each answer has a `video_url` and its length in `duration_seconds`, and `call_recording_url` is `null`. By phone call there is one recording of the whole call in `call_recording_url`, and every answer's `video_url` and `duration_seconds` are `null`. So check `call_recording_url` first: when it is set, there are no videos. A candidate who did both gets the more recent one.
- **Location.** `location_name` is the town the candidate was in when they allowed location on the verification link (`null` when they denied it, it could not be looked up, or they verified by phone call); coordinates are never returned.
- **Privacy.** Phone numbers are never returned.

### List mandate campaigns

`GET /mandates/{mandate_id}/campaigns`

List the campaigns that were sent for one job.

**Scope:** `results:read`

| Query | Type | Description |
|---|---|---|
| `limit` | `integer` | 1 to 100, default 50. |
| `cursor` | `string` | The next_cursor of the previous page. |

### Get a candidate journey

`GET /candidates/{candidate_id}/journey`

What Record has done with one candidate so far, in order: the WhatsApp invite, their reply, reminders, the SMS and each voice call, then what is waiting. Use it to explain a `pending` or `failed` status. It is read on request; the webhook carries only the final result. Phone numbers are never returned.

**Scope:** `results:read`

<CodeGroup>

```javascript JavaScript
const res = await call("GET", "/api/v1/partner/candidates/a3f1c9d2-7b44-4e0a-9c1d-5e6f7a8b9c01/journey");
const { data } = await res.json();
```

```python Python
res = call("GET", "/api/v1/partner/candidates/a3f1c9d2-7b44-4e0a-9c1d-5e6f7a8b9c01/journey")
data = res.json()["data"]
```

```bash cURL
pcall GET "/api/v1/partner/candidates/a3f1c9d2-7b44-4e0a-9c1d-5e6f7a8b9c01/journey"
```

```json 200 Response
{
  "success": true,
  "data": {
    "candidate_id": "a3f1c9d2-7b44-4e0a-9c1d-5e6f7a8b9c01",

    "status": "pending",
    "reason": null,
    "steps": [
      { "key": "whatsapp_sent", "label": "WhatsApp message sent", "state": "done", "at": "2026-10-05T09:30:00.000Z", "detail": null },
      { "key": "whatsapp_delivered", "label": "Delivered", "state": "done", "at": "2026-10-05T09:30:00.000Z", "detail": null },

      { "key": "link_not_opened", "label": "Link not opened yet", "state": "pending", "at": "2026-10-05T13:30:00.000Z", "detail": "Reminder 1 goes out" },
      { "key": "call", "label": "Call not answered", "state": "failed", "at": "2026-10-05T10:00:00.000Z", "detail": "Attempt 1 of 3" },
      { "key": "call_queued", "label": "Voice call queued", "state": "pending", "at": "2026-10-05T14:00:00.000Z", "detail": "Attempt 2 of 3" },
      { "key": "call_next", "label": "Next call, if no answer", "state": "scheduled", "at": "2026-10-05T18:00:00.000Z", "detail": null }
    ],
    "last_activity_at": "2026-10-05T09:41:00.000Z",
    "responded_at": "2026-10-05T09:41:00.000Z",
    "next_step": "voice_call",
    "link_opened": false
  }
}
```

</CodeGroup>

Match on `key`, never on `label` (display text that may be reworded). Steps come in the order they happen: what was done first, then what is waiting.

| `state` | Meaning |
|---|---|
| `done` | It happened. `at` is when. |
| `failed` | It did not work, such as a call not answered or a WhatsApp not delivered. |
| `pending` | Waiting on the candidate or on Record. `at` is when it is due, or `null`. |
| `scheduled` | Planned after a pending step. |

| `key` | Step |
|---|---|
| `queued` | Nothing has gone out yet. |
| `whatsapp_sent`, `whatsapp_delivered`, `whatsapp_failed` | The WhatsApp invite. |
| `tapped_yes`, `tapped_no`, `link_opened` | The candidate's reply and the link. |
| `reminder_sent`, `no_reply`, `link_not_opened` | Reminders and what Record is waiting for. |
| `sms_sent`, `sms_failed` | The SMS sent next to the WhatsApp message. |
| `call` | One voice call. |
| `call_queued`, `call_next` | The next call, and the one after it if there is no answer. |
| `completed` | The candidate finished the verification. |

`next_step` is `voice_call`, `reminder` or `null` (nothing is due). `status` and `reason` are the same as on the [result record](#the-record).

| Error | When |
|---|---|
| 404 `NOT_FOUND` | No such `candidate_id` for this key. |

Can also return the [common errors](/blue-collar-api/reference/errors). [Full schema](/api-reference/results/get-a-candidate-journey)

## Candidate rows and verdicts

One row per candidate with progress, verdict and score, and one candidate's full result with a rating per skill.

### List campaign candidates

`GET /campaigns/{campaign_id}/candidates`

One row per candidate: `candidate_id`, interested or not, progress, verdict and score, plus `delivery` (queued, sent, failed) and `can_resend`, so you can see who needs their link sent again. **Scope:** `results:read` or `campaigns:write`

|---|---|---|
| `status` | `string` | One of `interested`, `not_interested`, `no_answer_yet`, `unreachable`. |
| `progress` | `string` | One of `not_yet_started`, `in_progress`, `completed`. |
| `updated_since` | `string` | ISO 8601 date-time. |
| `limit` | `integer` | 1 to 200, default 100. |
