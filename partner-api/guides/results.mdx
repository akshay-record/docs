A result is what Record **collected** from the candidate: the answers to your screening questions, the skill-verification verdict and score, and other roles they are open to. It comes as one record per candidate. The best way to get it is the [webhook](/partner-api/guides/webhooks); these endpoints are for catching up and checking.

| Needs | You get | Scope |
|---|---|---|
| `campaign_id` from [step 3](/partner-api/guides/campaigns) | a record with `status` and `output` | `results:read` |

## Status

| Status | Meaning |
|---|---|
| `pending` | Invited or answering; not finished. Read endpoints only, never sent by webhook. |
| `completed` | Finished. `output` holds what Record collected. |
| `declined` | The candidate said they are not interested. |
| `failed` | No result could be got. `reason` is `undeliverable` (the invite could not be delivered) or `no_response` (every attempt went unanswered). |

- **Your own fields.** Send up to 10 fields of your own as `metadata` (with `external_id`) when you add a candidate: they come back unchanged on every result.
- **Sections.** A section of `output` appears only once its data exists and only if that check ran for the job.
- **Screening answers** are keyed by the question text. `qualified` is `true` when every yes/no answer is the wanted one (the opposite of its `knockout`, or `yes` when no knockout is set), and `null` when there is no yes/no answer to judge. `answers_native` holds the original-language text of voice answers.
- **Skill verification** gives the `verdict`, `total_score`, a `rating` per skill, how many questions were `answered` of `total`, and recordings: one video per question, or `call_recording_url` when the candidate verified by phone.
- **Location.** `location_name` is the town the candidate was in when they allowed location on the verification link (`null` when they denied it, it could not be looked up, or they verified by phone call); coordinates are never returned.
- **Privacy.** Phone numbers are never returned.

## Endpoints

### List mandate campaigns

`GET /mandates/{mandate_id}/campaigns`

List the campaigns that were sent for one job.

**Scope:** `results:read` · **Idempotency-Key:** not used

| Query | Type | Description |
|---|---|---|
| `limit` | `integer` | 1 to 100, default 50. |
| `cursor` | `string` | The next_cursor of the previous page. |

<CodeGroup>

```javascript JavaScript
const res = await call("GET", "/api/v1/partner/mandates/JM_261009101612456H3N8W2L5C9V1Z4/campaigns?limit=50");
const { data } = await res.json();
```

```python Python
res = call("GET", "/api/v1/partner/mandates/JM_261009101612456H3N8W2L5C9V1Z4/campaigns?limit=50")
data = res.json()["data"]
```

```bash cURL
pcall GET "/api/v1/partner/mandates/JM_261009101612456H3N8W2L5C9V1Z4/campaigns?limit=50"
```

## Candidate rows and verdicts

One row per candidate with progress, verdict and score, and one candidate's full result with a rating per skill.

### List campaign candidates

`GET /campaigns/{campaign_id}/candidates`

One row per candidate: `candidate_id`, interested or not, progress, verdict and score, plus `delivery` (queued, sent, failed) and `can_resend`, so you can see who needs their link sent again. Phone numbers are never returned. A key with only `campaigns:write` gets the rows with `verdict`, `total_score` and `report_url` left null.

**Scope:** `results:read` or `campaigns:write` · **Idempotency-Key:** not used

| Query | Type | Description |
|---|---|---|
| `status` | `string` | One of `interested`, `not_interested`, `no_answer_yet`, `unreachable`. |
| `progress` | `string` | One of `not_yet_started`, `in_progress`, `completed`. |
| `updated_since` | `string` | ISO 8601 date-time. |
| `limit` | `integer` | 1 to 200, default 100. |
| `cursor` | `string` | The next_cursor of the previous page. |

<CodeGroup>

```javascript JavaScript
const res = await call("GET", "/api/v1/partner/campaigns/asmnt_9f2c41d7a8b3e65f/candidates?limit=100");
const { data } = await res.json();
```

### Get a candidate verdict

`GET /candidates/{candidate_id}/result`

Verdict, score, a rating per skill and a report link. Add `include=answers` to also get what they said.

**Scope:** `results:read` · **Idempotency-Key:** not used

| Query | Type | Description |
|---|---|---|
| `include` | `string` | `answers` adds what the candidate said. Needs the `results:answers` scope. |

<CodeGroup>

```javascript JavaScript
const res = await call("GET", "/api/v1/partner/candidates/a3f1c9d2-7b44-4e0a-9c1d-5e6f7a8b9c01/result?include=answers");
const { data } = await res.json();
```

```python Python
res = call("GET", "/api/v1/partner/candidates/a3f1c9d2-7b44-4e0a-9c1d-5e6f7a8b9c01/result?include=answers")
data = res.json()["data"]
```
