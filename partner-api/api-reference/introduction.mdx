```text Base URL
https://api-bc.userecord.io/api/v1/partner
```

Every request is signed with your API key pair. Set up the `call()` helper from [Authentication](/partner-api/authentication#signing-helper) first: the code samples on each endpoint page use it.

## On each endpoint page

- **Scope**: the scope the key needs. Any one listed is enough.
- **Idempotency-Key**: whether the endpoint needs one, accepts one, or ignores it.
- **Responses**: the success answer and the errors specific to that endpoint. Errors any endpoint can return, such as `401`, `429` and `500`, are listed in [Errors](/partner-api/reference/errors).

## Endpoints

| Group | What it covers |
|---|---|
| Workflows | How and when candidates are contacted. |
| Job mandates | The job: skills, screening questions and checks. |
| Skills | Search and browse the skill taxonomy, and request missing skills. |
| Lookups | Places in India, countries, employment types and shifts. |
| Campaigns | Send candidates and manage the campaign. |
| Results | Result records, candidate rows and verdicts. |
| Webhooks | Endpoints that receive result events, and their delivery logs. |
| Events | Pull and acknowledge result events. |
| Analytics | Funnel, channel and drop-off numbers. |

## OpenAPI

The backend serves the machine-readable spec at `GET /api/v1/partner/openapi.json` and a Swagger UI at `/api/v1/partner/docs`. Neither needs a key.
