Read candidates while a campaign runs, and results once they finish. Both carry your `external_id` and the candidate's full phone number, so you can match them to your own records.

| Needs | You get | Scope |
|---|---|---|
| `enrichment_id` | `candidate_id`, `result_id` | `enrichment:read` (any enrichment scope also reads) |

<Note>
  Answers are **self-reported and not verified**. No verification link is ever returned.
</Note>

## Two ways to get results

| | Poll | Webhook |
|---|---|---|
| You call | [`GET /results`](#list-results) | Nothing. Record calls your URL. |
| When you hear | When you ask | Within about 15 seconds of a candidate finishing |
| Setup | Your key id and secret | An HTTPS endpoint, registered once ([Webhooks](/enrichment-api/guides/webhooks)) |
| Use it for | Catching up, reports, a safety net | Putting results into your ATS as they happen |

Both return the same record, so one parser serves both. Many integrations use the webhook and poll `/results` now and then to catch up.

## Candidate or result?

| | Candidate | Result |
|---|---|---|
| When it exists | As soon as the campaign is created | Only when the candidate finishes or declines |
| Changes | Yes, as the candidate moves through the [statuses](/enrichment-api/reference/statuses) | Never. Written once. |
| Use it for | Following progress, who to chase | Pulling the final answers into your ATS |

## Endpoints

### List candidates

`GET /enrichments/{enrichment_id}/candidates`

Every candidate of an enrichment and where each stands, most recently finished first.

**Scope:** `enrichment:read`

| Query | Description |
|---|---|
| `campaign_id` | Only this campaign's candidates. |
| `status` | One [status](/enrichment-api/reference/statuses): `queued`, `sent`, `link_opened`, `interested`, `in_progress`, `completed`, `not_interested`, `opted_out` or `failed`. |
| `search` | Part of the name or phone number. |
| `limit`, `cursor` | Paging. `limit` 1 to 100, default 25. |

```json Response · 200
{
  "success": true,
  "data": {
    "items": [
      {
        "candidate_id": "6f1d2c3e-8a4b-4c57-9d10-2b7e5a9c1f33",
        "external_id": "cand-1001",
        "name": "Ravi Kumar",
        "phone_number": "+919876543210",
        "status": "completed",
        "language": "english",
        "campaign_id": "EC_261110103045123M4P8T2K6Q9R",
        "is_completed": true,
        "completed_channel": "whatsapp",
        "answered_count": 2,
        "question_count": 2,
        "delivery_error": null,
        "answers": {
          "EQ_261110101530001A": ["Yes"],
          "EQ_261110101530002B": ["Forklift operator, 4 years, Chennai"]
        }
      }
    ],
    "count": 1, "total": 1, "next_cursor": null, "has_more": false
  }
}
```

`answers` is the answer text per `question_id`. `completed_channel` is where they finished: `whatsapp`, `sms`, `voice` or `web`.

### Get a candidate

`GET /enrichments/{enrichment_id}/candidates/{candidate_id}`

One candidate in full.

**Scope:** `enrichment:read` · **Errors:** `404 NOT_FOUND`

- `journey` shows what was sent and when: the invite, follow-ups, SMS, call attempts, link opened and opt-out.
- `answers` has every question, answered or not, with `text`, the `channel` it came on, an English transcript for a spoken answer (`transcript_english`) and, for `yes_no`, whether it `qualified`.
- `result` is the final result once the candidate has finished, otherwise `null`.

<Note>
  The English transcript of a spoken answer is translated the first time it is read, so that first read can be slower.
</Note>

### List results

`GET /enrichments/{enrichment_id}/results`

The final result of each candidate who finished or declined, newest first.

**Scope:** `enrichment:read`

| Query | Description |
|---|---|
| `campaign_id` | Only this campaign's results. |
| `limit`, `cursor` | Paging. `limit` 1 to 100, default 25. |

```json Response · 200
{
  "success": true,
  "data": {
    "items": [
      {
        "result_id": "ERS_261110110210123X5T9",
        "enrichment_id": "WF_BG_261110101530123K7M2P9Q4X7R5T8",
        "candidate_id": "6f1d2c3e-8a4b-4c57-9d10-2b7e5a9c1f33",
        "external_id": "cand-1001",
        "name": "Ravi Kumar",
        "phone_number": "+919876543210",
        "campaign_id": "EC_261110103045123M4P8T2K6Q9R",
        "status": "completed",
        "completed_channel": "whatsapp",
        "completed_at": "2026-11-10T11:02:10.000Z",
        "summary": { "answered_count": 2, "required_count": 2, "qualified_count": 1 },
        "answers": [
          { "question_id": "EQ_261110101530001A", "order": 0, "question_text": "Are you open to a new job right now?", "type": "yes_no", "value": true, "qualified": true, "channel": "whatsapp" },
          { "question_id": "EQ_261110101530002B", "order": 1, "question_text": "Tell us about the work you do and where you want to work.", "type": "voice", "value": "Forklift operator, 4 years, Chennai", "qualified": null, "channel": "voice" }
        ]
      }
    ],
    "count": 1, "total": 1, "next_cursor": null, "has_more": false
  }
}
```

| Field | Description |
|---|---|
| `enrichment_id` | The enrichment the result belongs to. |
| `status` | `completed`, or `not_interested` when the candidate declined. |
| `summary` | `answered_count`, `required_count`, `qualified_count`. When the candidate gave them also `open_to_work`, `work`, `location`, `disinterest_reason` and `partial` (finished with only some answers). |
| `answers[].value` | `true` or `false` for `yes_no`; a text summary for `voice`. |
| `answers[].qualified` | `yes_no` only: whether the answer matched the question's `preferred_answer`. |

Prefer to be told when a result exists? Receive each one as an [`enrichment.result` webhook](/enrichment-api/guides/webhooks), or poll this endpoint.
