---
title: "Error Handling & Response Codes"
description: "HTTP status codes and response shapes for all endpoints."
---

Every endpoint returns a consistent JSON envelope with a `success` boolean. On error, an `error` string describes what went wrong. HTTP status codes follow REST conventions.

## HTTP Status Code Reference

| Code | Meaning | When returned |
|---|---|---|
| 200 | OK | Successful GET or action |
| 201 | Created | Resource successfully created (POST that creates) |
| 400 | Bad Request | Validation failure, missing required field |
| 401 | Unauthorized | Missing, invalid, or expired credentials |
| 404 | Not Found | Resource does not exist or not accessible to the caller |
| 500 | Server Error | Unexpected internal error |

## Creator Backend (white-collar-assessment-portal-backend)

### POST /api/v1/sessions

| Status | Scenario | Response |
|---|---|---|
| 201 | Created | `{ "success": true, "data": { "token": "HKKPBaUppEt9", "candidates": [...] } }` |
| 401 | Missing x-api-key header | `{ "success": false, "error": "Missing required headers: x-api-key, x-secret-key" }` |
| 401 | Wrong secret key | `{ "success": false, "error": "Invalid secret key" }` |
| 400 | No users provided | `{ "success": false, "error": "Provide either name and email, or a non-empty users array" }` |
