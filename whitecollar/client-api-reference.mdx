This page is the integration guide for **clients** (organisations embedding the assessment portal). It covers both the **Creator backend** (`/api/v1`) and the **Candidate backend** (`/api`).

---

## Base URLs

| Environment | Creator backend | Candidate backend |
|---|---|---|
| Local | `http://localhost:8080/api/v1` | `http://localhost:8081/api` |
| Production | `https://assess-api.getrecord.in/api/v1` | `https://exam-api.getrecord.in/api` |

---

## Authentication overview

| Strategy | Endpoints | Headers required |
|---|---|---|
| `verifyApiKeyAndSecret` | `POST /sessions` | `x-api-key`, `x-secret-key` |
| `verifySignature` | `GET /assessments` (signed) | `x-api-key`, `x-timestamp`, `x-signature` |
| `verifySession` | All other creator endpoints | `x-session-token` |
| `x-session-token` (candidate) | All `/exam/session/*` endpoints | `x-session-token` (JWT issued after OTP) |

## Creator — Sessions

### Create session

```http
POST /api/v1/sessions
x-api-key: wc_8c076d034ada3a234cb9a288383e4aeb59553349
x-secret-key: 9e345f2b48dd318d301a2bdd2e90a29a45f15e4db88473ad9c132278b00a76b5
Content-Type: application/json
```

**Single candidate**

```json
{ "name": "Saran", "email": "saran@getrecord.in" }
```

**Multiple candidates (recommended)**

```json
{
  "users": [
    { "name": "Saran",   "email": "saran@getrecord.in" },
    { "name": "Avinash", "email": "avinash@getrecord.in" },
    { "name": "Monesh",  "email": "monesh@getrecord.in" }
  ]
}
```

**Response `200`**

```json
{
  "token": "HKKPBaUppEt9",
  "sessionId": "sess_xxxx",
  "candidateId": "cand_xxxx",
  "expiresAt": "2026-06-09T12:00:00.000Z"
}
```

Use the returned `token` to embed the modal iframe:

```html
<iframe
  src="https://assess.getrecord.in/assess?token=HKKPBaUppEt9&company=Acme+Corp"
  width="900"
  height="700"
/>
```

Listen for the close event from the modal:

```js
window.addEventListener('message', (e) => {
  if (e.data?.type === 'WC_ASSESS_CLOSE') {
    document.querySelector('iframe').remove();
  }
});
```

## Creator — Assessments

### List all assessments (signed)

This endpoint requires HMAC-SHA256 signing. Body keys must be sorted alphabetically. Timestamp window is 5 min (prod) / 30 min (dev).

**Signature construction**

```
payload = "GET:/api/v1/assessments:<timestamp>:"
signature = HMAC-SHA256(secretKey, payload)
```

```http
GET /api/v1/assessments
x-api-key: wc_xxx
x-timestamp: 1749123456789
x-signature: <hex-digest>
```

**Response `200`**

```json
[
  {
    "assessmentId": "asmnt_72b47a64306f",
    "jobTitle": "Backend Engineer",
    "status": "sent",
    "createdAt": "2026-06-05T08:00:00.000Z"
  }
]
```

### Generate questions with AI

```http
POST /api/v1/assessments/:assessmentId/generate
x-session-token: <session-token>
```

No body required. Questions are generated asynchronously via OpenAI. Poll `GET /exam/session/status` on the candidate backend to check readiness.

**Response `202`**

```json
{ "message": "Generation started", "assessmentId": "asmnt_72b47a64306f" }
```

## Candidate — Exam flow

All candidate endpoints are on the **Candidate backend** (`/api`). The `x-session-token` here is the JWT issued after OTP verification — it is different from the creator session token.

### Get assessment metadata

```http
GET /api/exam/:assessmentId
```

No auth required.

**Response `200`**

```json
{
  "assessmentId": "asmnt_72b47a64306f",
  "jobTitle": "Backend Engineer",
  "durationMinutes": 60,
  "totalMarks": 100,
  "passMarks": 60,
  "orgName": "Acme Corp"
}
```

---

### Request OTP

```http
POST /api/exam/:assessmentId/request-otp
Content-Type: application/json
```

```json
{ "email": "saran@getrecord.in" }
```

**Response `200`**

```json
{ "message": "OTP sent to saran@getrecord.in" }
```

---

### Verify OTP — get candidate session token

```http
POST /api/exam/:assessmentId/verify-otp
Content-Type: application/json
```

```json
{ "email": "saran@getrecord.in", "otp": "482913" }
```

**Response `200`**

```json
{
  "sessionToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "candidateId": "cand_xxxx",
  "name": "Saran"
}
```

Use `sessionToken` as `x-session-token` on all subsequent candidate calls.

## Error responses

All endpoints return errors in this shape:

```json
{
  "error": "Unauthorized",
  "message": "Invalid or expired session token.",
  "statusCode": 401
}
```

| Status | Meaning |
|---|---|
| `400` | Bad request — missing or invalid fields |
| `401` | Auth failed — invalid key / expired token |
| `403` | Forbidden — signature mismatch or timestamp expired |
| `404` | Resource not found |
| `409` | Conflict — e.g. OTP already sent |
| `500` | Internal server error |

## Quick-start checklist

1. Obtain your `x-api-key` and `x-secret-key` from the WhiteCollar dashboard.
2. Call `POST /api/v1/sessions` to create a session and get a `token`.
3. Embed the iframe with the token and your company name.
4. Listen for `WC_ASSESS_CLOSE` to know when the creator finishes.
5. Register a webhook URL to receive `assessment.submitted` events.
6. Verify every webhook signature before processing results.
